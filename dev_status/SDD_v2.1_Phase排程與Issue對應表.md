## 三件從時間線看到的事

### 1. 實際進度不照 Phase 走，而且那不完全是問題

Phase 0 的五個門檻只過了一個（而且是補記錄的那個），但 Phase 1 的後端全清、Phase 3 的三張資料表（S3／S4／S5）也做完了。

§13.1 本來就說腦袋與臉可以完全平行，只有身體是單點匯流。所以**真正被 Phase 0 擋住的是臉與身體，不是腦袋**。

但 §13.2 那句「Phase 0 結束後，Phase 1–7 需複審」仍然成立：P0-A 若沒過就要切 CC4，已經寫進 §7 的產線規格要回頭改。而 CL#23 改為人工產出資產，實質上已經繞開了 P0-A 想驗證的東西——**這代表 P0-A 的門檻定義本身需要重寫，而不只是重排時程。**

### 2. Phase 6／7 只有一張票

6 個 Sprint、約 18 個工作天的量，目前只有 B8 有票。QA、多機種測試、封測招募、現場行為指引、事故應變流程、`usage_tiers` 調校、Prompt 參數調整，全部沒有。

距離還遠，但排程上它佔了總工期的 **22%**。

### 3. 兩個逾期的內容缺口

§16 標的時機已經過了：

| 缺口                                  | §16 標的時機 | 現況              |
| ------------------------------------- | ------------- | ----------------- |
| `canned_greetings` 觸發語與預寫回覆 | Phase 3 前    | 尚未撰寫（BE#48） |
| 龍山寺內容治理七項（§12.2）          | Phase 3 前    | BE#41 開著        |

B12 快速問候比對層（BE#13）已經做完了，但它比對的內容不存在——**機制先於內容完成，是這個專案目前最一致的模式**：B3 人格卡載入完成但人格卡沒驗收過、B12 完成但沒有問候語、配額機制在做但沒有 fallback 文案。
