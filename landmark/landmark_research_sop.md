# 地標史實研究範本 — 建立流程（SOP）

> 適用對象：任何要幫新地標開一份「史實研究記錄範本」的人（不限 Lead）
> 這份流程產出的是**查資料階段的暫存文件**，不是正式資料。正式資料的終點是 `brain.landmark_souls` / `brain.city_souls`，中間還要經過 Lead 審核。

---

## 0. 這一步在整個人格建立管線裡的位置

```
① 史實蒐集 ← 這份 SOP 處理的就是「開範本」這一步，讓②③開始時有地方寫
② 寫成來源檔（landmarks/*.yaml，格式待定）
③ 寫入 brain.landmark_souls / brain.city_souls
④ 從史實提煉人格草稿（archetype / speech_style / values...）
⑤ 設計安全邊界（taboos / not_this_character / imagination_license）
⑥ 撰寫 canned_greetings
⑦ 寫成 personas/{spirit_id}_v0.yaml
⑧ persona_loader 讀入 brain.character_personas
⑨ 人工審核（reviewed_by / reviewed_at）
⑩ 人工 flip active = true（無自動路徑，這是刻意設計）
```

**這份範本主要餵給 ①，但範本裡標出來的敏感點會直接影響 ⑤ 的 taboos 設計，所以查資料的人不需要懂人格設計，但要看得懂自己在標記什麼。**

---

## 1. 建立範本的步驟

### Step 1｜確認地標基本資訊

- 地標中文名稱
- 行政區（之後對應 `brain.districts`，會影響地理圍欄判斷，標錯要盡快回報修正，不要留到 GPS 實測才發現）
- `spirit_id`，三條規則（既有 11 個的定案值見 `README.md`）：
  1. **`{專名}_{類型}`，全稱不縮寫。** 對齊既有的 `longshan_temple`。縮寫看起來省事，但 `npm`（原本故宮的暫定值）在任何有 JavaScript 的環境裡都是別的東西，`tp`、`tfam` 是同一類問題。
  2. **不用營運品牌名，用文資登錄名。** 榕錦時光生活園區 → `taipei_prison_quarters`（登錄名「原臺北刑務所官舍」）。品牌會換約、會改名，登錄名不會。
  3. **不用角色名。** SDD §7.3.1：角色名可能變更，不得進入技術命名。
  > `spirit_id` 是資料庫主鍵，定案後再改就是資料遷移。開始寫 `landmarks/*.yaml` 之前一定要拍板。客戶端的 Addressables key 是另一套識別碼，不受這裡影響。

### Step 2｜判斷敏感類型（決定要加哪些特別提醒段落）

這一步是整份 SOP 最重要的判斷，往下對照第 2 節的分類表。**同一個地標可能同時屬於多個類型**，不是單選。

### Step 3｜套用標準範本結構

不管敏感類型是什麼，骨架都一樣，對應 `brain.landmark_souls` 的四個欄位加上一個 `city_souls` 素材區：

| 章節 | 對應欄位 | 內容 |
|---|---|---|
| 0. 欄位結構 | — | 說明擴充後的 `{year, event, detail, source, confidence}` 結構 |
| 1. 建物/建廟沿革 | `founding_facts` | 表格，逐年條列 |
| 2. 其他重大事件 | `key_events` | 同上格式 |
| 3. 文化意義 | `cultural_significance` | 150–250 字自由敘述 |
| 4. 城市基調素材 | `brain.city_souls` | 關鍵詞＋整段敘述，同區地標可共用 |
| 5. 爭議區 | 不進資料庫 | `confidence` 非 official/mainstream 的項目集中放這裡 |
| 5.5 誤解區 | `common_misconceptions` | 廣為流傳但**經查證為錯**的說法，見 Step 3.5 |
| （視類型加） 6. 特殊敏感區 | 不進資料庫 | 見 Step 4 |
| 最後. 下一步 checklist | — | 標準流程勾選項，視類型追加項目 |

### Step 3.5｜記錄誤解區（對應 `common_misconceptions`）

**跟爭議區不是同一件事。** 爭議區放的是「說法有分歧、還不知道哪個對」；誤解區放的是「**已經查證確定是錯的，但很多人這樣以為**」。前者等 Lead 判斷，後者是定論，直接進資料庫。

查資料時遇到這種東西的訊號：你自己原本也這樣以為，查了官方資料才發現不對。那一刻請停下來記一筆——**這正是玩家最可能拿來問角色的東西**，而角色答錯的代價比答不出來高得多。

| 欄位 | 內容 | 注意 |
|---|---|---|
| `misconception` | 誤解本身，用一句話 | 照著大家實際會講的方式寫，不要先修飾成正確版本 |
| `correction` | 為什麼錯，附關鍵事實 | 要有可查證的依據（年份、公告、文獻） |
| `say_instead` | 角色被問到時該怎麼講 | 見下方說明 |
| `source` | 來源 | 同其他章節 |

**`say_instead` 一定要填，它不是 `correction` 的重複。** `correction` 是給我們自己看的依據，`say_instead` 是角色實際會說出口的方向。糾正玩家很容易講成訓話，而這類條目的難處就在怎麼開口。範例：

```text
misconception  蔣渭水曾經被關在臺灣新文化運動紀念館現存的這棟建築裡
correction     蔣渭水 1931 年逝世，現存建築 1932 年動工、1933 年完工。
               關過他的是第一代木造北警察署（今家樂福重慶店位置），已拆除。
say_instead    「關過他的是上一代的北署，那棟已經不在了」
```

> ⚠️ 這一區的內容會被注入 prompt，而 `misconception` 欄位裡放的**就是那句錯的話**。所以它必須留在自己的欄位裡，不要為了省事併進第 1、2 節的史實表格——那兩節整段注入時，模型會把每一條都當成可以直接講的事實。理由詳見 `citysoul_data_schema.md` §7。

---

### Step 4｜依敏感類型加註特別提醒

在檔案最上方（行政區之後、章節 0 之前）加一段警示區塊，內容依第 2 節分類表對應。**沒有特殊風險的地標可以省略這段**，不用為了格式一致硬掰警語。

### Step 5｜命名與存放

- 檔名：`{地標中文名}_史實研究記錄範本.md`（多字地標可用底線分隔，如「臺灣新文化運動紀念館」不需要）
- 存放：本 repo 的 `landmark/` 目錄，單一真相來源，不要多處複製。
- 檔名：英文小寫加底線，例如 `longshan_temple.md`。內容用中文沒問題，檔名不行——中文檔名會在跨平台工具鏈上踩到編碼問題（理由同 `story/story_arc_writing_sop.md` Step 7）。

## 2. 敏感類型分類參考表

> 依目前已建立的 12 個地標歸納，供之後新地標對照判斷。一個地標可能落在多類。

| 類型 | 判斷依據 | 需要的特別處理 | 已建立範例 |
|---|---|---|---|
| **A. 一般型** | 沒有明顯宗教/政治/歷史創傷成分 | 標準流程即可，不需額外警示段 | 松山文創（多數內容）、台北當代藝術館（建物本身部分） |
| **B. 宗教內容治理型** | 宗教場所，SDD §12.2 直接適用 | 標明「§12.2 七項全部照走」；若有特定神祇職能（如月老），額外標記高頻問題方向，`canned_greetings` 優先設計 | 龍山寺、霞海城隍廟 |
| **C. 政治敏感型** | 涉及當代政治立場、兩岸關係、威權歷史評價、更名/定位爭議 | 區分「查資料時遇到」vs「玩家可能主動問」；只記中性事實進 `founding_facts`；政治性內容獨立放「政治敏感區」，**優先交 Lead 決策**，必要時討論是否比照 §12.2 另訂治理章節 | 中正紀念堂（最高級）、故宮（外部/兩岸型）、臺灣新文化運動紀念館（較輕，多為歷史人物當代政治援引） |
| **D. 歷史創傷型** | 場址曾發生政治迫害、處決等歷史事件，尤其現況與歷史定位有落差（如商業化包裝 vs 沉重歷史） | 現況資料與歷史資料要分開查；歷史內容放「歷史敏感區」附來源；提醒人格語氣拿捏（不能只講「這裡好拍照」也不能全篇沉重）需 Lead 決策 | 榕錦時光（原台北刑務所官舍，最需留意） |
| **E. 特殊專業邊界型** | 不涉政治宗教，但有領域特定的「不做專業裁決」邊界 | 明確指出該地標最可能被問到的越界問法方向，供之後 taboos 設計參考 | 天文台（天文 vs 占星）、北美館／台北當代藝術館（藝術鑑價/真偽判斷）、剝皮寮（地名由來多重民間說法、都更/居民權益敘事） |

> **殖民時期歷史（日治）是跨類型的共通提醒**，不單獨成類——它可能疊加在 A/D/E 之上（如台北當代藝術館的建成小學校歷史屬輕度 D、松山文創的菸廠產業史也是輕度 D），統一原則是：**歷史定性用詞保守，版本分歧一律先進爭議區，不下判斷性敘述**。

## 3. 查資料時的檢查點（給實際動手查的人）

```
□ 這個地標的行政區有沒有跟實際 GPS 位置對上？(對應 brain.districts 地理圍欄)
□ 我查到的內容，是「機構/建物本身的沿革」，還是「當期會變動的活動/展覽/評價」？
   → 只有前者進 founding_facts / key_events，後者屬 B9 當日情境範疇，不寫進史實層
□ 我看到的說法，是單一來源還是多方一致？
   → 對照 confidence 分級（official / mainstream / disputed / political / sensitive_history）
□ 查的過程中，有沒有哪一條是我原本以為 A、查了才發現是 B？
   → 有的話那是誤解區的材料（Step 3.5），連 say_instead 一起記，不要只記正確版本
□ 這個地標屬於第 2 節哪一類（可複選）？相應的警示段落有沒有寫進範本？
□ 這個內容如果被拿去直接注入 prompt、原封不動講給玩家聽，我會不會不放心？
   → 會的話，先進爭議區/敏感區，不要自己決定要不要收，交給 Lead
```

## 4. 常見誤區

- **查到誤解只改掉、不記下來**：發現「原來不是這樣」的當下，最自然的反應是把正確版本寫進史實表就算了。但那條錯誤說法不會因此消失——它還在網路上，玩家還是會拿來問。記進誤解區才有用。

- **把誤解丟進爭議區**：兩者不同。爭議區是「還不知道哪個對」，誤解區是「已經確定錯了」。丟錯地方的後果是它會停在等 Lead 判斷的狀態，而它其實不需要判斷。

- **把「查不到反對意見」當成「沒有爭議」**：資料來源如果集中在單一立場的網站（如只查到官方論述或只查到單一政治陣營論述），不代表沒有爭議，這種情況也該標 disputed/political，附上你查到的來源讓 Lead 判斷。
- **把當期活動當史實**：美術館/文創園區類地標最容易犯，看到「正在展出 XX 特展」就想寫進 `founding_facts`——不要，那是會過期的內容，走 B9。
- **技術命名用了角色名**：`spirit_id`／檔名一律用地標本身或拼音，不要用之後可能會變動的「角色暱稱」（SDD §7.3.1 明訂的規則）。
- **政治敏感內容自己先下判斷**：查資料的人不需要、也不應該自己決定「這段歷史該怎麼定性」，該做的只是誠實記錄來源、丟進對應的敏感區，交給 Lead。
